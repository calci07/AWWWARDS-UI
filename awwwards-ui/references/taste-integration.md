## Conditional application

Apply a taste rule only when it supports the brief, approved route, repository truth, responsive behavior, accessibility, and optical balance.

| Taste guidance | Code-first application |
|---|---|
| Typography, palette, materiality, anti-slop | Tokens, font loading, asset direction, and rendered hierarchy |
| Layout, grid, spacing, cards | Responsive CSS/layout primitives and reusable component anatomy |
| Breakpoints and mobile overrides | Mobile-first source order and deliberate breakpoint recomposition |
| Loading, empty, error, active, focus | Real component states and testable interactions |
| React/RSC/client boundaries | Apply only when the repository uses the relevant framework |
| Tailwind/CSS conventions | Follow the repository's established styling system |
| Icon rules | One coherent editable SVG/code-icon family |
| Motion/GSAP/Framer guidance | Use only when installed, compatible, and justified by the approved route |
| GPU/repaint/listener/z-index guidance | Performance budgets, stable layers, cleanup, and rendered testing |
| Dependency rules | Verify existing packages before adding any; avoid needless dependencies |

Preserve content authenticity: no fake metrics, endorsements, identities, capabilities, evidence, or polished filler presented as fact. Anti-AI-pattern rules are a filter, not permission to swap one cliche for another.

Preserve content, routes, functionality, and SEO when product truth requires it; this is not preserving layout or current section silhouettes. For a redesign, the approved transformation mode controls the visible design delta.

## Calibrate, never inherit blindly

Do not automatically inherit `DESIGN_VARIANCE: 8`, `MOTION_INTENSITY: 6`, `VISUAL_DENSITY: 4`, anti-center composition, Bento layouts, perpetual motion, or a preferred framework/library.

For every route publish:

- 1-10 values for variance, motion, and density;
- product, audience, content, device, and risk reasons;
- visible effects on mobile, tablet, desktop, and wide screens;
- balance/accessibility countermeasures;
- what each dial explicitly does not authorize.

High variance requires stable reading order, repeated rhythm, bounded measure, counterweights, and mobile simplification. High motion requires purpose, interruption, touch and keyboard parity, and reduced-motion behavior. High density requires grouping, scan paths, touch-safe spacing, and recovery sections.

## Conflict precedence

Resolve conflict in this order:

1. explicit user requirements and approved direction;
2. truthful content, functionality, accessibility, and safety;
3. approved transformation contract and optical balance;
4. repository architecture and maintainability;
5. selected precedent evidence;
6. upstream Taste defaults and examples.

Do not force off-center composition when ceremonial symmetry is stronger. Do not add motion because a dial exceeds five. Do not impose Bento on a narrative, table, timeline, or continuous image story. Do not migrate frameworks or styling systems merely to satisfy a taste example.

Record every material Taste waiver with its reason, affected invariant or Transformation Map row, and acceptance impact. A waiver may not reduce an approved Overhaul to a cosmetic restyle or bypass its transformation floor. Overhaul may never waive page and section composition or mobile recomposition, and waivers may not reduce its final tally below six `verified` dimensions. Truthful functionality, accessibility, responsive usability, and repository safety remain hard gates at every precedence level.
